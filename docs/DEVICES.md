# بروتوكول أجهزة الدخول والبصمة

طبقة تكامل عامة (JSON عبر HTTPS) تخدم: قارئات QR/الباركود، بطاقات RFID، أجهزة البصمة، والبوابات الدوّارة.
الجهاز — أو جسر صغير بجانبه (Raspberry Pi/حاسوب صغير) إن كان الجهاز لا يرسل HTTP — يرسل ما قرأه، والنظام يرد
بالسماح أو الرفض ويسجّل القرار. **فتح المرحّل مسؤولية الجهاز/الجسر** عند `allowed: true`.

> لم يُختبر مع جهاز فعلي. الـ API مختبر آليًا (`tests/Feature/DevicesTest.php` و`IntegrationsTest.php`) وبجولة محلية
> تستدعيه كما يستدعيه الجهاز. التوافق يعتمد على موديل الجهاز، ولا يُفترض لأي موديل قبل معرفة الشركة والبروتوكول واختباره.

## التسجيل
1. **التطبيقات التكاملية ← أجهزة البصمة والبوابات ← جهاز جديد**: الاسم، النوع، الفرع، الاتجاه، الاستخدام (أعضاء/موظفون/كلاهما).
2. يظهر **رمز الجهاز** مرة واحدة فقط (يُخزّن الهاش فقط). يمكن إصدار رمز جديد في أي وقت (يُبطل القديم).
3. لكل عضو QR تلقائي في بوابته. للبطاقة/البصمة: «ملف العضو ← وسائل الدخول» (المعرّف كما يقرؤه الجهاز).
4. للموظفين: «أجهزة البصمة والبوابات ← بصمات وبطاقات الموظفين».

## المشغّلات (Drivers)
كل جهاز له مشغّل (`gym_access_devices.driver`) يقرأ طلبه ويحوّله إلى قراءة (`App\Modules\Gym\Access\Drivers`). المتوفر
اليوم مشغّل واحد: **البروتوكول العام** (`generic_json`) الموصوف هنا. مشغّل موديل بعينه يُضاف فقط بعد معرفة الشركة والموديل
والبروتوكول واختباره على الجهاز نفسه.

## الأمان
- **لا أمر فتح**: النظام يرد بقرار السماح أو الرفض فقط، ولا يرسل أمر فتح لأي بوابة. فتح المرحّل قرار الجهاز أو الجسر.
- **لا بيانات بيومترية**: البصمة تُسجَّل وتُطابق داخل الجهاز. النظام يحفظ رقم المستخدم في الجهاز فقط (حروف وأرقام حتى
  32 خانة)، ويرفض أي قيمة أطول (مثل قالب بصمة) في اللوحة وفي الـ API (422).

## المحاكاة
«محاكاة قراءة» في صفحة الأجهزة تجرّب قراءة كأن الجهاز أرسلها: لمن المعرّف وما الذي سيُرد به. لا تسجّل دخولًا ولا حضورًا،
ولا تغيّر «آخر اتصال» للجهاز. حالة «متصل» لا تأتي إلا من اتصال حقيقي برمز الجهاز.

## الطلبات

كل الطلبات: `Authorization: Bearer <device-token>`، `Content-Type: application/json`، الحد 120 طلبًا/دقيقة/جهاز.

### `POST /api/devices/v1/access` — قرار دخول
```json
{ "credential_type": "qr", "credential": "<محتوى QR أو رقم البطاقة أو معرّف البصمة>" }
```
`credential_type`: `qr` | `card` | `fingerprint` | `pin` | `barcode`

رد السماح:
```json
{
  "allowed": true, "reason": "ok", "message": "مسموح",
  "member": { "id": 12, "name": "سارة", "member_no": "M-00012", "photo_url": null },
  "membership": { "plan": "الشهرية", "ends_on": "2026-11-27", "days_left": 30, "sessions_left": null }
}
```
رد الرفض (HTTP 200):
```json
{ "allowed": false, "reason": "membership_expired", "message": "العضوية منتهية", "member": {…}, "membership": {…} }
```
أسباب الرفض: `unknown_credential`، `member_blocked`، `member_inactive`، `no_membership`، `membership_expired`،
`membership_frozen`، `membership_not_started`، `pending_payment`، `dues_outstanding` (إن فُعّل في الإعدادات)،
`device_not_for_members`.

إذا كان المعرّف لموظفة والجهاز مخصص للموظفات، يُسجَّل حضور/انصراف ويُرد `{"allowed": true, "reason": "staff", …}`.

**المسح المكرر:** إذا مُسحت نفس المشتركة مرة أخرى خلال نافذة التكرار (افتراضيًا 5 دقائق، من «الإعدادات ← قواعد النادي»،
و0 للإيقاف) يُرد `{"allowed": true, "reason": "duplicate_scan", …}`: يفتح الجهاز البوابة، وتُحفظ المحاولة في السجل
بنتيجة «مكرر»، لكنها **لا تُحتسب** دخولًا جديدًا ولا تُسجّل حضور الحصص مرة أخرى. القراءتان المتزامنتان تُحتسبان مرة
واحدة (قفل على صف المشتركة).

### `POST /api/devices/v1/staff-punch` — حضور/انصراف موظفة
```json
{ "credential_type": "fingerprint", "credential": "FP-17" }
```
```json
{ "ok": true, "type": "in", "name": "هند", "at": "2026-10-28T08:01:00+04:00" }
```
البصمة الأولى في اليوم = حضور، والتالية = انصراف.

### `POST /api/devices/v1/heartbeat`
يحدّث «آخر اتصال» للجهاز في اللوحة. يظهر الجهاز «متصل» إذا اتصل خلال آخر 10 دقائق.

## السجل
كل قرار يُحفظ في «سجل الدخول» (الطريقة، الجهاز، النتيجة، السبب)، وآخر القراءات تظهر في «سجل قراءات الأجهزة». المعرّفات
المجهولة تُحفظ مقنّعة (آخر 4 خانات). الدخول المسموح يسجّل حضور حجز العضو في الحصة القريبة تلقائيًا.

## أجهزة شائعة
- **قارئ QR/باركود USB (Keyboard wedge)**: يعمل مباشرة مع شاشة الاستقبال (حقل المسح يبقى نشطًا) دون أي تكامل.
- **ZKTeco وما يماثلها**: تحتاج جسرًا يقرأ حدث البطاقة/البصمة (SDK أو بروتوكول ADMS) ويستدعي `/access` ثم يفتح المرحّل.
  جسر ZKTeco غير منفّذ؛ يُضاف كمشغّل (`gym_access_devices.driver`) عند تحديد الموديل.
