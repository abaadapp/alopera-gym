# حالة النظام — Alopera Gym SaaS

آخر تحديث: 28 أكتوبر 2026 (مراجعة ما قبل الإطلاق). التفاصيل الكاملة في [FEATURES.md](FEATURES.md) و[REMAINING.md](REMAINING.md).

## الخلاصة

منصة SaaS مستقلة لإدارة الأندية الرياضية، متعددة الأندية من البداية، بالعربية وبواجهات متجاوبة. الوظائف الأساسية مكتملة
ومختبرة آليًا وعمليًا في المتصفح. ما تبقى قبل الإطلاق التجاري هو **ربط الحسابات الخارجية الحقيقية** (الدفع وواتساب والنشر)
وجولة قبول قصيرة بيد مستخدمات حقيقيات.

## الوظائف المكتملة

| المجال | ما يعمل |
|---|---|
| المنصة (SaaS) | لوحة مدير المنصة، إنشاء الأندية ومالكاتها، باقات المنصة الشهرية والسنوية وفواتيرها، الإيقاف وإعادة التفعيل، الدومين الخاص، سجل البوابات والعمليات |
| عزل الأندية | كل بيانات النادي مرتبطة به ولا تظهر لنادٍ آخر (يفشل مغلقًا)، مع منع الكتابة لنادٍ آخر واختبارات مخصصة |
| المشتركات والعضويات | الملف الكامل والمستندات وسجل التواصل، البيع والتجديد والتجميد والاستئناف والإلغاء وتغيير الباقة مع احتساب الرصيد، أكواد الخصم، التفعيل بعد تأكيد الدفع فقط |
| الحصص والتدريب | البرامج والمدربات وأوقاتهن، الجدول الأسبوعي، السعة و«مكتملة»، الحجز من الاستقبال والبوابة، الحضور والغياب، التدريب الشخصي مع الإغلاق المبكر للمخوّلين مع السبب |
| المالية | الفواتير والإيصالات، النقد والبطاقة (برقم العملية) والتحويل البنكي بتأكيد المالية، **الإشعارات الدائنة** للاسترداد الجزئي مع فصل رد المال ومنع تكراره، المستحقات، المصروفات |
| المخزون ونقطة البيع | المنتجات بالصور، الموردون، المشتريات واستلامها، البيع في الاستقبال، الإلغاء بإشعار دائن |
| التقارير | المؤشرات المالية والتشغيلية مع المقارنة بفترة سابقة (افتراضيًا بنفس المدة، أو الشهر/العام السابق أو فترة مخصصة)، التصدير CSV وExcel |
| الأدوار والصلاحيات | المالكة والإدارة والاستقبال والمالية والمدربة وأدوار مخصصة، مفروضة في الخادم — [PERMISSIONS.md](PERMISSIONS.md) |
| الموقع وبوابة المشتركة | موقع عربي لكل نادٍ بمحتوى قابل للتعديل وSEO، التسجيل أونلاين، بوابة فيها رمز QR والعضوية والحجز والتجديد والفواتير |
| الدخول والأجهزة | مسح QR في الاستقبال، واجهة برمجية عامة للبوابات والبصمة، حضور الموظفات، تجاهل المسح المكرر خلال نافذة قابلة للتعديل مع حفظ كل محاولة |
| واتساب (طبقة النظام) | القوالب والأتمتة والتذكيرات والحملات مع احترام الموافقة، صندوق المحادثات والردود الآلية، سجل الرسائل |
| التشغيل | سجل عمليات لا يُعدّل، نسخ احتياطي واستعادة لكل نادٍ، مهام مجدولة، ملفات نشر DigitalOcean وCI |

## مراجعة ما قبل الإطلاق (28 أكتوبر 2026)

ما أُصلح بعد مراجعة كل اللوحات والموقع والبوابة عمليًا:

- **الجداول على الجوال**: كانت الخلايا تنكسر على عدة أسطر (أرقام الفواتير والهواتف والأسماء)؛ الآن سطر واحد لكل صف مع
  تمرير أفقي داخل البطاقة، والأرقام محاذاة مع عناوين أعمدتها.
- **التواريخ**: كانت بالأرقام الهندية (٢٨ أكتوبر ٢٠٢٦) بينما بقية الأرقام لاتينية؛ صارت كلها لاتينية ومتسقة.
- **بطاقات المؤشرات على الجوال**: بطاقتان في كل صف بدل بطاقة كبيرة لكل مؤشر (لوحة النادي، المنصة، التقارير، المستحقات)،
  والرقم محاذى مع عنوانه.
- **صفحة المنصة العامة**: كانت تعرض كل الأندية (ومنها التجريبية)؛ الآن لا يظهر نادٍ إلا بموافقته (خيار في لوحة المنصة)،
  وأزرار الاشتراك لا تظهر بلا بريد مبيعات، وأُضيف البريد في التذييل.
- **موقع النادي**: بطاقة «دفع إلكتروني آمن» كانت تظهر حتى بلا بوابة دفع؛ الآن لا تَعِد بالدفع الإلكتروني إلا إذا كان مفعّلًا.
  الشارة وبطاقات «لماذا نحن» قابلة للتعديل من محرر الموقع (لم تعد مخصصة للنساء إجباريًا)، وقسم «من نحن» بلا صورة لا يُظهر
  إطارًا فارغًا، وأيقونة تبويب بشعار النادي أو حرفه ولونه، وصورة المشاركة تعود لشعار النادي، و`robots.txt` يمنع فهرسة اللوحات.
- **طباعة الفاتورة**: هاتف العميلة صار تحت اسمها، وجدول الدفعات يُظهر رقم عملية البطاقة أو مرجع التحويل بأعمدة واضحة،
  وفترة العضوية تُكتب «من … إلى …» (السهم كان يُقرأ معكوسًا بالعربية).
- **أمان الإنتاج**: أمر `platform:preflight` يفحص إعدادات الإنتاج ويرفض أي حساب تجريبي نشط، ويشغّله `deploy.sh` قبل
  تبديل الإصدار فيوقف النشر عند أي خلل؛ و`--deactivate-demo` يعطّل الحسابات التجريبية إن وصلت بالخطأ (دون حذف).
- اختبار حضور الموظفات كان يفشل إذا شُغّل بعد الرابعة عصرًا (يعبر منتصف الليل)؛ ثُبّت توقيته.

## التحقق

- **161 اختبارًا آليًا ناجحًا** على PostgreSQL، منها اختبارات العزل والصلاحيات والإشعارات الدائنة وأمان الإنتاج وفحص الجاهزية.
- **رحلة كاملة من الصفر في Chrome (32/32)**: المنصة تنشئ ناديًا ← المالكة تضيف باقة وبرنامجًا وحصة ← تسجيل مشتركة ←
  بيع عضوية وإصدار فاتورة ← تحصيل نقدي وتفعيل ← تجديد مدفوع بالبطاقة (برقم العملية) يُجدول بعد الحالية ← حجز الحصة
  وتسجيل حضورها ← دخول QR ومسح مكرر لا يُحتسب ← طباعة الفاتورة ← البوابة من الجوال (العضوية والحجز والفاتورتان) ←
  موظفة استقبال جديدة لا ترى التقارير والإعدادات والخادم يرفضها (403) ← التقارير ← العزل بين الأندية في الاتجاهين.
- **مسح كل الصفحات**: 106 صفحات للوحة النادي بكل الأدوار + 20 صفحة للمنصة والموقع والبوابة، بمقاسي الكمبيوتر والجوال:
  بلا أخطاء وبلا تمرير أفقي للصفحة.
- **الجولة السابقة**: مراجعة عملية لكل الصفحات والأدوار أُصلح فيها أكثر من 35 مشكلة، وسيناريو شامل (20/20) شمل
  الاسترداد الجزئي بإشعار دائن.
- **أمان الإنتاج**: جُرّب تشغيل النظام في وضع الإنتاج؛ الحسابات التجريبية رُفضت رغم صحة كلمة المرور وسُجّلت المحاولات،
  وأوامر مسح قاعدة البيانات ممنوعة.

## تكاملات تحتاج حسابات حقيقية

الكود جاهز ومختبر بالمحاكاة؛ **لم تُجرَّب على حسابات حقيقية**.

| التكامل | المطلوب من النادي/المالك | التحقق بعد الإدخال |
|---|---|---|
| Paymob عُمان (الدفع الإلكتروني) | حساب تاجر، Secret/Public/HMAC وIntegration IDs | دفعة تجريبية بوضع الاختبار ووصول الإشعار الموقّع وتفعيل العضوية |
| WhatsApp Business Platform | حساب Meta Business، رقم واتساب، System User Token، Phone Number ID، App Secret وVerify Token، واعتماد القوالب | رسالة ترحيب حقيقية وظهور «وصلت/قُرئت» |
| DigitalOcean | Droplet وManaged PostgreSQL وSpaces | تنفيذ [DEPLOYMENT.md](DEPLOYMENT.md) واستعادة تجريبية قبل الإطلاق |
| الدومين وSSL | دومين النادي وسجلات DNS | فحص HTTPS على الدومين |
| البريد (SMTP) | خادم بريد | رسالة استعادة كلمة مرور |
| أجهزة الدخول | موديل الجهاز (QR/بصمة/بوابة) | ربط الجهاز بالواجهة البرمجية — [DEVICES.md](DEVICES.md) |

## لم يُختبر بعد

- الدفع والإرسال الحقيقيان (Paymob وواتساب) وأي جهاز دخول فعلي.
- النشر على خادم حقيقي.
- جولة قبول بيد مستخدمات حقيقيات على آيفون وأندرويد وتابلت الاستقبال — [ACCEPTANCE.md](ACCEPTANCE.md).

## الاستقلالية والأمان

- مستودع وقاعدة بيانات وإعدادات مستقلة؛ لا يعتمد على أبعاد ولا يحتوي كودًا أو تفاصيل خاصة منه
  (نُظّف تاريخ المستودع من وصف داخلي سابق بعد أخذ نسخة احتياطية).
- لا أسرار ولا بيانات عملاء ولا ملفات بيئة في المستودع؛ أسرار التكاملات مشفّرة لكل نادٍ ولا تُرسل للمتصفح.
- تصميم الوحدات يسمح بدمجها مستقبلًا في تطبيق مضيف — [ABAAD.md](ABAAD.md).

## قبل الإطلاق

1. إدخال حسابات Paymob وواتساب للنادي الأول واعتماد القوالب.
2. النشر على DigitalOcean بحسب [DEPLOYMENT.md](DEPLOYMENT.md) وإنشاء مدير المنصة بكلمة مرور قوية.
3. استعادة تجريبية من نسخة الإنتاج.
4. جولة القبول اليدوية في [ACCEPTANCE.md](ACCEPTANCE.md).
