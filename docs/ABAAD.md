# العلاقة مع مشروع أبعاد (ABAAD)

## الاستقلالية
- مشروع الجيم مستقل تمامًا: مستودع وقاعدة بيانات وإعدادات وبيئة تشغيل خاصة به، ولا يعتمد على أبعاد في التشغيل أو البناء.
- لم يُنسخ أي كود أو إعداد أو سر أو بيانات من أبعاد، ولم يُعدّل أي ملف فيه. كل كود هذا المستودع مكتوب له، والتشابه الوحيد
  هو هيكل Laravel الافتراضي (مفتوح المصدر) وأنماط Laravel العامة.
- خوارزمية توقيع Paymob (HMAC-SHA512 وترتيب الحقول) مأخوذة من توثيق Paymob العام، وتوقيع Meta (`X-Hub-Signature-256`)
  من توثيق Meta العام.
- اعتُمدت نفس التقنيات والإصدارات لتسهيل الدمج لاحقًا: Laravel 13، Inertia 3، React 19، TypeScript، Tailwind 4، PHPUnit 12.

## تصميم قابل للدمج مستقبلًا
الوحدة مبنية لتُنقل إلى تطبيق Laravel مضيف (مثل أبعاد) دون إعادة تطوير، عبر عقود صغيرة يُنفّذها المضيف:

1. **وحدة الجيم** (`app/Modules/Gym`) مستقلة: نماذجها وخدماتها ومتحكماتها ومساراتها وترحيلاتها (`gym_*`) ومزوّدها.
   تُنسخ كما هي وتُسجّل `GymServiceProvider`. البادئة `gym_` تمنع تعارض أسماء الجداول مع المضيف.
2. **العقود التي يوفّرها المضيف**:
   - **العزل** ← `BelongsToTenant` و`TenantContext`: يُربط مفتاح المؤسسة في المضيف بـ `tenant_id` (محوّل أو إعادة تسمية العمود).
   - **المالية** ← الجيم لا يعرف إلا `InvoiceService::issue(Billable, lines)` و`PaymentService::record`
     والحدثين `InvoicePaid`/`InvoiceVoided`. يمكن للمضيف تنفيذ هذا العقد فوق نظام فواتيره.
   - **الرسائل** ← `MemberNotifier` يستدعي `WhatsAppService::queueTemplate`؛ يمكن توجيهه إلى طبقة واتساب لدى المضيف.
   - **الدفع** ← `OnlinePaymentService` قابل للاستبدال بخدمة الدفع لدى المضيف مع الحفاظ على `recordGatewayPayment`.
   - **الصلاحيات** ← مفاتيح الجيم (`members.*`، `memberships.*`، `classes.*`…) تُضاف إلى كتالوج صلاحيات المضيف.
3. **الواجهات**: صفحات `resources/js/Pages/Gym/*` تعتمد على مكونات `@/Components/ui` وتخطيط `ClubLayout`؛
   تُربط بالمكونات المقابلة لدى المضيف.
4. **الاختبارات** (`tests/Feature/*`) تنتقل مع الوحدة، وتُعدّل مساعدات `BuildsClubs` لإنشاء مؤسسة المضيف.

تفاصيل الدمج الفعلية تُعدّ داخل مستودع أبعاد الخاص عند الحاجة، لا في هذا المستودع العام.
